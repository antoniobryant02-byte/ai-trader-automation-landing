Real internal build #2

From crypto scanner to GPT-5.5 Telegram + Discord digest.

I rebuilt a crypto scanner into an automated alert system that collects technical data, lets Hermes GPT-5.5 interpret it, and delivers scheduled digests to Telegram and Discord — now with a clearly separated speculative meme-coin watchlist.

Before

The scanner could analyze crypto, but it depended on manual runs and an OpenRouter LLM path that hit credit limits.

python3 -m glm_alpha_engine scan --symbols BTC-USD,ETH-USD Issue: OpenRouter 402 credit limit Issue: custom CLI symbols were treated as STOCK

After

The system now separates data collection from AI interpretation.

12:00 AM CT → Telegram overnight watch 12:05 AM CT → Discord overnight watch 8:00/8:05 → morning crypto pulse 12:00/12:05 → mid-day crypto pulse 8:00/8:05 → evening crypto recap Model: Hermes GPT-5.5 / openai-codex
Architecture

The GPT-5.5 collector pattern.

1. Data source: yfinance crypto OHLCV
2. Technical engine: RSI, EMA, momentum, Bollinger, ATR, volatility regime
3. Collector script: ~/.hermes/scripts/crypto_scout_data.py
4. AI layer: Hermes GPT-5.5 / openai-codex
5. Delivery: Telegram + Discord #hermes-chat
6. Logs: latest technical JSON + status files
Speculative sleeve

Meme coins are watched separately, not blended into majors.

DOGE, SHIB, and PEPE were added with explicit metadata so GPT-5.5 can label them as high-volatility speculative assets instead of treating them like BTC, ETH, or SOL.

asset_class: CRYPTO_MEME risk_bucket: SPECULATIVE_MEME meme_coin: true watchlist: DOGE-USD, SHIB-USD, PEPE-USD Digest rule: separate “Speculative meme coin watch” section. Safety rule: informational only, no financial advice, no trade execution.

What this proves

This pattern survives API limits.

The valuable move was separating reliable data collection from the AI summary layer. When one LLM route failed, the workflow still produced real market data and GPT-5.5 handled the final interpretation.
